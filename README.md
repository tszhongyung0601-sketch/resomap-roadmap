# ResoMap 產品路線圖 T0–T5

公開頁面：**https://tszhongyung0601-sketch.github.io/resomap-roadmap/**

## 這是什麼

ResoMap 從今天的 Demo 到完整商業產品的六階段路線圖，切法依據是**依賴性**：
一個功能只會落在「它所有前置都已經存在」的最早那一階。所以順序不是偏好排序，
是物理限制——把 86 個功能的依賴圖拓撲排序之後，在自然斷開的位置切下去。

| 檔案 | 內容 |
|---|---|
| `index.html` | 路線圖本體。給老闆／投資人看的版本：為什麼這樣拆、關鍵路徑、六個階段各自的商業模式與驗證指標、完整功能表 |
| `features.csv` | 86 項功能，每一列標明 T 階段、依賴哪些功能、為何不能更早、做完解鎖什麼、前提條件、變現角色、工量、被誰依賴 |
| `stages.csv` | 六個階段的目標、過關條件、為什麼是這一階、商業模式、收入線與前提、驗證指標 |
| `roadmap.json` | 上面三份的資料來源 |
| `build.py` | 由 `roadmap.json` 產生前三份 |

CSV 是 UTF-8 with BOM，Excel 直接打開不會亂碼；也可直接匯入 Notion 或 Jira。

## 怎麼看

線上版在上面那個網址，任何人都打得開。也可以直接用瀏覽器開 `index.html`，
它不連外、不載任何字型或腳本。淺色深色都做過，跟系統設定走。
要 PDF 就在瀏覽器列印，版面已經處理過分頁不切斷段落。

頁面帶 `noindex`，所以拿到連結的人打得開，但不會出現在搜尋結果裡。

## 重新產生

改 `roadmap.json` 之後：

```bash
python build.py
```

`build.py` 開頭有兩個 assert，會在產出前擋下兩種錯誤：
任何功能排在它的前置之前（階段順序違規），以及指向不存在功能的依賴（斷鏈）。
目前兩者皆為 0。這是刻意的——一份路線圖最容易出的錯，就是內文主張的順序被自己的表格推翻。

## 誠實界線

文件裡所有「聯盟」都是指**向各平台的公開聯盟計畫申請**，需要逐一送審、可能被拒。
ResoMap 目前與 Klook、KKday、Booking.com、Agoda、Trip.com **皆無任何合作關係**，
文件內不得出現官方合作、合作夥伴、策略聯盟、獨家或即時最低價。

T0 的內容由程式碼盤點讀出，不是自述。單位經濟寫成可被推翻的算式放在 T3，
其中四個參數今天全部是猜測，分別要到 T2、T3、T4 才量得到。
